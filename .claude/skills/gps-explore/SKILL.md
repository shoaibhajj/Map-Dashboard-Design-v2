# GPS Explore — turn an unclear idea into an authored direction

Applicability guard: if the current request has no visual/interaction/design-session intent, do not load the design context merely because GPS/IoT is mentioned. Return to the ordinary task workflow. Honor read/propose/review-only mode before any write.

## Read

context/design/ENTRY.md and BRAND.md, current task, target screenshots/code, relevant PRODUCT-BASELINE.md, REGISTRY.md and DECISIONS.md. Read REFERENCES.md only if using references; MAP-IOT.md or DASHBOARD.md for those domains.

## 1. Identify the real brief

Separate user problem, visual desire and behavioral change. Example: "important issues on the map" needs a definition of critical/location/action availability; "new cluster shape" normally preserves aggregation.

Do not re-ask documented facts. Ask at most the few questions whose answers change correctness/safety/scope. A missing severity source or persistence model can be blocking. A reversible shape/lighting choice usually is not. State uncertainty instead of claiming a guess is confirmed.

## 2. Extract principles, not a competitor layout

For a reference: observable feature → useful principle → our transformation. Static images don't prove interaction/timing. No claims of watching a video or testing a reference without evidence.

## 3. Produce 2–3 genuinely different concepts

For each: central idea / first focal point / user path / domain meaning / preserved functions / motion trigger / depth technique / static alternative / expected cost / primary risk.

Different means composition and information relationship, not three colors of the same card. Keep recognizable controls. Future/IoT identity can be expressive; don't dilute it to generic minimalism, or substitute meaningless decoration.

Recommend one based on task clarity, identity, usability and cost. No promise of universal novelty/conversion.

## 4. Resolve execution mode

Proposal-only: present and stop. If user chooses, hand off a short contract to gps-design.
If user explicitly asks to invent and implement, choose the best reversible option and continue under gps-design without a redundant aesthetic approval ceremony. Still obtain required approval for global identity changes, consequential new behavior, dependencies or external effects.

## Output

Brief interpretation → concepts → recommendation → assumptions/blockers → next scoped action. Use context/design/templates/concept-card.md if a saved artifact is authorized. Don't write registry/decisions simply because a conversation explored an idea. Identity A02 is already accepted; don't seek reapproval each time.
