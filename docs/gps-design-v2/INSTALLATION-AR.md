# دليل التركيب والترقية

## 1. افهم بنية الحزمة

```text
GPS-Platform-Design-v2/
  START-HERE-AR.md
  CHANGELOG.md
  PACK-MANIFEST.json
  context/design/                 ← السياق والسجلات والقوالب
  .agents/skills/gps-*/SKILL.md    ← النسخة الأصلية للمهارات الثماني
  integrations/                  ← فقرة دمج التعليمات
  docs/                          ← أدلة وأمثلة واختبارات سلوك
  tools/install_pack.py          ← تركيب اختياري، معاينة افتراضياً
  tools/verify_pack.py            ← فحص بنيوي وبصمات الملفات
```

ليس هناك AGENTS.md أو CLAUDE.md بديلان في الجذر؛ نريد الحفاظ على تعليمات المشروع الموجودة.

## 2. تحقّق من الحزمة

داخل مجلدها بعد فك الضغط:

```sh
python tools/verify_pack.py
```

يتحقق من الملفات والبصمات وصيغة المهارات والروابط المعلنة. نجاحه ليس اختباراً بصرياً ولا اختباراً لسلوك Claude/Codex.

## 3. تركيب تلقائي اختياري بوضوح

استبدل المسار بمسار مشروعك الموجود. اختر الأداة التي تستخدمها، لا تنفّذ أوامر المهارات داخل Terminal.

```sh
python tools/install_pack.py --target "/path/to/project" --agent codex
python tools/install_pack.py --target "/path/to/project" --agent codex --apply
```

لـClaude Code استبدل `codex` بـ`claude`. ولأداة عامة استخدم `manual`.

السلوك:
- الأمر الأول معاينة فقط، لا يكتب شيئاً.
- --apply ينسخ السياق، والمهارات في المكان المناسب، والأدلة داخل docs/gps-design-v2.
- الملفات المطابقة تُتجاوز. أي ملف مختلف موجود يوقف العملية قبل النسخ؛ لا خيار force.
- لا يعدّل ملفات الوكيل أو package.json ولا يشتري/يثبّت/يدفع/يرفع إلى GitHub.
- لا ينسخ سكربتات التشغيل إلى مشروعك؛ تبقى أدوات تركيب وفحص للحزمة الأصلية.
- راجع قائمة الملفات والتعارضات. خذ نسخة/فرعاً مناسباً بطريقتك؛ لا ينشئ السكربت commit تلقائياً.

## 4. تركيب يدوي بديل

انسخ context/design إلى مشروعك بعد المقارنة، ثم اختر:

### Codex

انسخ مجلدات gps-* من .agents/skills إلى .agents/skills في جذر مشروعك. استدعاء نموذجي داخل Codex:

```text
$gps-design غيّر شكل مؤشر المركبة داخل الخريطة فقط
```

يمكن استخدام /skills أو قائمة $ للتحقق من ظهور المهارة حسب الواجهة. تجنّب نسخ الاسم نفسه في أكثر من نطاق. المسار موثّق في المصدر الرسمي، لكن إعدادات بيئتك قد تغيّر الإتاحة.

### Claude Code

انسخ مجلدات gps-* نفسها إلى .claude/skills في مشروعك، ثم:

```text
/gps-design غيّر شكل مؤشر المركبة داخل الخريطة فقط
```

لا حاجة إلى إعادة تسمية SKILL.md. لا تنسخ النسختين في أماكن متعددة لنفس الأداة بلا سبب. هذه تعليمات لجلسات Claude Code المحلية؛ حسابات/جلسات السحابة قد تملك آلية إتاحة مختلفة.

### أدوات أخرى

لا نفترض أنها تدعم صيغة slash أو المسارات نفسها. ضع الملفات في المسار الذي توثّقه أداتك، أو استخدم مجلد design-skills الذي ينشئه installer في وضع manual واطلب قراءة الملف المطلوب صراحة. حدّث المسارات في تعليماتك إذا غيّرتها.

## 5. دمج التوجيه الصغير

اقرأ integrations/AGENT-INSTRUCTIONS-SNIPPET.md، ثم ادمج قسم GPS / IoT design routing في AGENTS.md/CLAUDE.md أو الملف الذي تبدأ منه أداتك.

- لا تنسخ الغلاف التوضيحي باعتباره تعليمات مشروع إضافية غير لازمة.
- احتفظ بتعليمات الهندسة والأمان الحالية.
- لا تضف أمراً يقول «اقرأ كل context/design في كل رسالة»؛ هذا يفسد الانتقائية.
- اسم المهارة/وصفها يساعدان الاختيار، لكن لا يضمنان التفعيل الصحيح. نفّذ اختبارات السلوك.

## 6. الترقية من v1

هذه حزمة بديلة مستقلة، ولا تحتاج ملفات v1 لكي تعمل.

1. قارن مجلد context/design الحالي بالحزمة؛ لا تستبدل سجلات قرارات/مكونات تمت الموافقة عليها أثناء العمل.
2. انقل السجلات المفيدة إلى REGISTRY.md وDECISIONS.md مع حالتها وأدلتها؛ لا تترجم كل الموجود إلى owner-approved.
3. غيّر الإشارة من DESIGN-ENTRY.md القديم إلى ENTRY.md الجديد في تعليمات الوكيل.
4. لا تترك ملفات v1 وv2 القديمة متساوية السلطة. أرشف القديم خارج مسار القراءة النشط بعد مراجعته.
5. لا تمسح ملفات المنتج/البنية/الأمان الفعلية في المستودع.
6. installer يوقف التعارضات، بما فيها السجلات الحالية؛ ادمجها يدوياً بدل فرض الاستبدال.

## 7. ماذا عن Skills المشروع السابق؟

لا تنقل مهارات JobPilot كما هي باعتبارها المسار الإجباري لهذا التصميم.

| السابق | الإجراء هنا |
|---|---|
| architect | gps-explore عند الغموض + gps-design حسب حجم المهمة |
| imprint | gps-imprint يسجّل المعنى والحركة والنسخ، لا الكلاسات فقط |
| recover | gps-recover يشخّص فشل الفكرة/الهوية/السلوك/الأداء |
| remember | gps-handoff لسياق التصميم فقط دون استبدال memory.md العام |
| review | gps-review للمراجعة البصرية والسلوكية بأدلة |

الأسماء gps-* تقلل التعارض، لكنها لا تمنع الوكيل من استدعاء مهارة قديمة تلقائياً. قيّد وصف/توجيه المهارات القديمة أو عطّلها في نطاق المشروع حسب أداتك إذا ظلت تفرض مسارها. لا تحذف مهاراتك العامة دون مراجعة.

## 8. الصور والأصول

صور المرجع في المحادثة ليست مضمنة. يمكن إضافتها في مكان تختاره بالمشروع مع مسارات حقيقية وحقوق الاستخدام. لا تنسخ صور المنافسين إلى واجهة المنتج لمجرد استخدامها مرجعاً.

## 9. نجاح التركيب

تحقق أن ENTRY.md قابل للقراءة، والهوية معتمدة مع ملمس IoT، والمهارات الثماني ظاهرة أو يمكن قراءتها صراحة، وطلب حسابي لا يستدعي التصميم، وطلب تعديل سهم لا يطلق إعادة بناء المنصة.

المصادر الرسمية: https://developers.openai.com/codex/skills وhttps://code.claude.com/docs/en/skills . تحقق من سلوك الإصدار/البيئة التي تستخدمها.
