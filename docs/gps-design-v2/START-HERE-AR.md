# GPS-Platform-Design-v2 — ابدأ هنا

الإصدار 2.0.0 — 2026-10-26

## ما هذه الحزمة؟

منظومتان متكاملتان لتطوير المنصة الموجودة:
1. Context: حقائق الهوية والمنتج، وقواعد التصميم والتفاعل والأداء، وسجلات القرارات.
2. Skills: إجراءات محددة يستدعيها الوكيل عندما تناسب الطلب، لا سلسلة أوامر إجبارية لكل مهمة.

ليست تطبيق GPS جديداً، ولا مكتبة React جاهزة، ولا تنفيذاً للإنذارات أو تخصيص Dashboard. هي نظام توجيه لإنجاز هذه المهام داخل مشروعك الحالي.

## الهوية المعتمدة منك

«هوية تشغيلية دقيقة، بعمق بصري هادئ وطابع مستقبلي أقرب إلى الخيال العلمي، تحمل روح منظومة IoT متصلة، وتربط الأجهزة والموقع والحركة والزمن والبيانات والتحكم، دون التضحية بوضوح الاستخدام».

أصبح هذا الاتجاه معتمداً، وليس اقتراحاً ينتظر الموافقة. أما أمثلة المكونات، ودرجات التعبير، وميزانيات الأداء، فلم تتحول تلقائياً إلى تصاميم معتمدة.

## تركيب سريع وآمن

من داخل مجلد الحزمة بعد فك الضغط، شغّل معاينة أولاً:

```sh
python tools/install_pack.py --target "/path/to/existing-project" --agent codex
```

أو لـClaude Code:

```sh
python tools/install_pack.py --target "/path/to/existing-project" --agent claude
```

راجع الملفات المقترح نسخها، ثم أضف `--apply` إلى الأمر نفسه للتنفيذ. السكربت لا يكتب افتراضياً، ولا يستبدل ملفاً مختلفاً موجوداً، ولا يدمج AGENTS.md/CLAUDE.md تلقائياً، ولا يشغّل npm أو git أو خدمات خارجية.

لأداة أخرى استخدم `--agent manual` واقرأ docs/INSTALLATION-AR.md؛ سيضع ملفات المهارات في مجلد مرجعي، دون الادعاء بأن أداتك تكتشفها تلقائياً.

بعد النسخ ادمج نص integrations/AGENT-INSTRUCTIONS-SNIPPET.md يدوياً في ملف التعليمات الذي تقرؤه أداتك. لا تستبدل تعليمات المشروع الحالية.

## أول استخدام

اطلب:

> افحص توجيه طلبات التصميم حسب context/design/ENTRY.md. لخّص الهوية المعتمدة وحدود النطاق. لا تعيد تصميم شيء الآن، ولا تدّعِ تفعيل Skills قبل التحقق من ظهورها.

ثم جرّب مهمة صغيرة مثل:

> غيّر شكل مؤشر المركبة من دائرة إلى سهم صغير واضح. حافظ على التحديد والحالات والنقر، ولا تعرض اتجاهاً غير معروف كأنه اتجاه موثوق. استخدم الهوية الحالية ولا تعِد تصميم الخريطة كلها.

## المهارات الثماني

| المهارة | وظيفتها |
|---|---|
| gps-design | تنفيذ تصميم جديد أو إعادة تصميم؛ يختار المسار الصغير أو الموسّع |
| gps-explore | فهم الطلب المبهم وتوليد اتجاهات مختلفة قبل التنفيذ |
| gps-adapt | تكييف مكوّن خارجي دون نسخ هويته أو استيراد عبئه دون مبرر |
| gps-dimension | اختيار وتصميم العمق/3D بالحجم والتقنية المناسبين |
| gps-review | مراجعة دون تعديل مع أدلة ودرجات خطورة وحدود التحقق |
| gps-imprint | تسجيل الأنماط أو تدقيق الموجود، دون اعتماد تلقائي أو تصليح تلقائي |
| gps-recover | تشخيص فشل وظيفي أو تصميمي أو أداء أو انحراف مفاهيمي |
| gps-handoff | حفظ/استعادة سياق التصميم دون أسرار ودون تشغيل التنفيذ تلقائياً |

في Claude Code: `/gps-design ...`. في Codex: `$gps-design ...`. هذه صيغة استدعاء للأدوات الداعمة، وليست أوامر Terminal. في الأداة العامة اطلب قراءة SKILL.md المحدد واتباعه. التفاصيل في دليل الاستخدام.

## لا تجعل المهارات عبئاً

- طلب حسابي أو backend أو شرح عام لا يغيّر واجهة: لا تحميل سياق التصميم ولا تشغيل مهاراته.
- تعديل صغير محدد: المسار السريع؛ لا ثلاثة مفاهيم ولا جلسة architect كاملة.
- طلب مبهم/مبتكر: استكشاف؛ ثم تنفيذ حسب ما فوّضت به.
- تخصيص Dashboard: مهمة سلوكية وتصميمية، لا تغيير ألوان فقط.
- طلب «اقرأ فقط»: قراءة فقط؛ لا سجلات ولا ملفات ذاكرة جديدة.

## أين التفاصيل؟

- docs/INSTALLATION-AR.md: التركيب والترقية من v1 وتعارضات المهارات السابقة.
- docs/USAGE-AR.md: اختيار المهارات والتعامل مع المهام الجديدة والقديمة.
- docs/EXAMPLES-AR.md: أمثلتك الخمسة بصيغ جاهزة.
- docs/ACCEPTANCE-TESTS.md: سيناريوهات اختبار اختيار المهارة وعدم تفعيلها خطأ.
- context/design/ENTRY.md: المرجع التشغيلي للوكيل.
- context/design/SOURCES.md: الأدلة وحدود الفحص ومراجع التقنية.

## حدود التسليم

الحزمة كاملة من ناحية الوثائق والمهارات والأدلة وسكربت تركيب محلي وفحص بنيوي. لا تعني أن الواجهة أعيد تصميمها، ولا أن المهارات اختُبرت داخل جلسة حقيقية من كل وكيل. الأداء والإتاحة والأصالة تُراجع أثناء كل تنفيذ، ولا يضمنها وجود الملفات وحده.
